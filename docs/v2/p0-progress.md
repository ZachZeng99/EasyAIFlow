# EAF 2.0 P0 实现进度

更新：2026-10-16。总体设计见 [设计与分阶段计划](../superpowers/specs/2026-10-16-eaf-2.0-design.md)。

## 已实现：持久化消息同步

- 复用 V2 store 的会话版本号，写盘完成后发布消息变更，接入 Electron IPC 与 Web SSE。
- 快照和实时消息使用同一版本体系；忽略重复与过期变更，版本缺口、历史替换和重连触发有界快照恢复。
- 刷新结果不会按客户端时钟覆盖更新的消息；分页拒绝混入其他版本的数据。
- Codex 的流式文本、commentary 和工具过程实时持久化；版本化会话由服务端返回实际消息，不再依赖前端临时消息匹配。
- 持久化前固定消息内容，防止调用方在等待磁盘写入时修改同一个对象；修复崩溃恢复后快照内容与版本不一致的问题。

本轮采用“持久化版本 + 快照补齐”，尚未提供按游标逐条重放历史 SSE 事件。原生历史解析和身份映射仍沿用现有实现，需要在真实 CLI 联调时继续验证。

## 验证

- 新增 17 项用例：重复、缺口、快照与实时更新竞态、时钟偏差、重启续接版本、写盘失败，以及真实 HTTP/SSE 断线恢复。
- 现有消息合并、分页、V2 存储/迁移/并发压力、Codex app-server、群聊、运行态恢复和 SSE 回归通过。
- `npm run check` 与 `npm run build:web` 通过。
- 尚未完成真实 Claude/Codex 账号、Electron 界面与两台物理设备的端到端验收；P0 未完成。

## 后续 P0

1. 完成 Claude SDK 与直接调用 CLI 的隔离试验，确认认证、resume/fork、交互请求及实际协议行为。
2. 抽出独立设备常驻服务，验证客户端关闭后任务继续，明确原生历史恢复与活动运行时的写入归属。
3. 增加持久化操作请求与状态核对，覆盖重复提交、取消、审批及确认丢失，防止任务重复执行。
4. 录制真实 CLI 协议，验证旧会话迁移、手机双端操作和高频输出下的写入/网络性能，再进行 P0 总体验收。

模型自动更新、原生子 agent 完整视图和群聊重建按总体计划进入 P1。

agent 间定向通信、跨 provider/跨设备投递与回复等待属于 P3；当前消息同步实现尚不具备这些能力。
