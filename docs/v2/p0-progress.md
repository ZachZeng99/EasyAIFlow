# EAF 2.0 P0 实现进度

更新：2026-10-16。总体设计见 [设计与分阶段计划](../superpowers/specs/2026-10-16-eaf-2.0-design.md)。

**当前是开发中间版本，不是 2.0 上线版。** 多设备统一管理和 EAF 自主协作通信尚未交付。

## 可使用的新功能：原生子 agent

- 会话右上角“子 agent”展示 Claude/Codex 原生子任务的父子关系、模型、独立文本和状态；它们由原生 CLI 管理。
- 子 agent 内容通过现有消息日志持久化，不会混入主回复；刷新与服务重启保留记录，中断后未确认的状态明确标记。长会话可分页读取 agent 记录，不依赖聊天窗口最后一页。
- Claude 按实际 CLI 能力开启子 agent 转发；Codex 使用原生协作事件和有数量限制的子线程读取。前台 Agent 与后台命令分别处理。
- Codex 主回复先结束时保持执行连接，等待仍在运行的子 agent；停止操作同时寻址原生子回合。真实前台/后台子任务、输出隔离、重启恢复与桌面/手机布局验证通过。
- 当前展示 EAF 捕获的原生记录；未批量补录旧 CLI 历史中的所有子会话。大输出按窗口限制显示，这些限制会在面板提示。

## 可使用的新功能：多设备与手机接入

- 顶部切换执行设备；桌面和网页共用配对、授权与远程路由，手机用一次性浏览器登录码接入。操作、模型和事件按设备隔离，切换后迟到的请求不会跑到另一台电脑。
- 支持 HTTPS、自签名公开证书或显式配置的加密 VPN；本机默认不开放网络。可撤销接入授权，浏览器退出同时作废旧会话。
- 两个隔离服务/网关及真实 Claude/Codex 已通过断线继续执行、重连恢复与同操作防重；桌面/手机尺寸 UI 已验证。两台物理电脑与真实手机仍待联合验收。使用见 [设备接入](device-access.md)。

## 可使用的新功能：群成员配置

- 群聊右上角“群成员”可配置最多 8 位成员，包括多个 Claude 或多个 Codex；每人独立会话、模型、推理档位和角色说明。
- 支持自定义 `@标识`、启用/停用与模型刷新；停用保留历史。运行中禁止修改，多个客户端同时编辑会检查配置版本。
- 同类成员可独立执行，群聊生成期间可继续发送并可停止；成员配置与回复归属经过刷新、存储重启及真实 CLI 验证。
- 这是用户定向派发的可配置群聊，尚不代表 agent 已能自主调用发送/等待/回复接口。

## 已实现：持久化消息同步

- 复用 V2 store 的会话版本号，写盘完成后发布消息变更，接入 Electron IPC 与 Web SSE。
- 快照和实时消息使用同一版本体系；忽略重复与过期变更，版本缺口、历史替换和重连触发有界快照恢复。
- 刷新结果不会按客户端时钟覆盖更新的消息；分页拒绝混入其他版本的数据。
- Codex 的流式文本、commentary 和工具过程实时持久化；版本化会话由服务端返回实际消息，不再依赖前端临时消息匹配。
- 持久化前固定消息内容，防止调用方在等待磁盘写入时修改同一个对象；修复崩溃恢复后快照内容与版本不一致的问题。

目前采用“持久化版本 + 快照补齐”，尚未提供按游标逐条重放历史 SSE 事件。

## 已实现：常驻服务与操作防重

- 桌面与 Web 共用独立设备服务，通过带本机密钥的管道/Unix socket 连接；关闭窗口或 Web 网关只断开客户端，CLI 留在服务内继续运行。
- 操作 ID 在执行前落盘；并发重复请求共用结果，确认丢失和界面重载继续使用原 ID。服务重启后未确认的操作标记为待确认，不自动重跑。
- 重试返回最新目录数据，避免旧操作结果覆盖后来创建的项目/会话；操作日志在执行前保存原始输入，结果中的目录副本压缩为稳定身份。
- 增加 `npm run service:status`、`npm run service:stop`；有任务或操作运行时拒绝停止服务。`npm run smoke:providers` 在隔离的 EAF 数据目录中执行真实 CLI 冒烟测试。

## 实测发现与修复

真实 Codex 测试发现：回复已完成，但原生导入把 EAF 消息 ID 替换为文件行号 ID，导致刷新后无法关联回复。现已持久化会话历史归属：EAF 接管后的历史由运行时维护，自动导入不能替换消息；重启后归属保持，重叠项目也不重复导入同一受管会话。

这意味着受管会话在外部 CLI 继续执行后，暂不自动覆盖 EAF 历史；显式交接/恢复入口仍需补齐。尚未被 EAF 接管的原生会话继续正常导入。

## 提前完成的 P1：模型自动更新

- 从 Claude `initialize` 和 Codex `model/list` 获取目录；启动、每 15 分钟和手动刷新更新列表，CLI 版本变化触发刷新。按设备、工作区和本机登录配置签名隔离缓存，失败时保留上次结果。
- 新建空会话采用运行时推荐的完整模型 ID；已有会话保留原 ID，原生别名由 CLI 解析。模型和推理档位不再依赖界面里的固定版本名单。
- Claude 斜杠命令一并读取初始化结果，不再通过生成一次“OK”回复探测。刷新显示更新时间与缓存状态。
- 运行时自身未提供的模型仍需先由 CLI 支持；EAF 会自动读取升级后的目录。
- 修正 Windows 多份 Codex 并存时误用旧 npm CLI 的问题：比较 PATH 与已安装桌面运行时的版本，发现和执行共用所选程序；可用 `EASYAIFLOW_CODEX_PATH` 明确指定。运行时路径变化隔离缓存，空闲会话在下一轮切换，运行中的任务继续使用原进程。
- 选择器显示目录来源与 CLI 版本；新建单聊和群成员采用运行时推荐模型，已有会话保持选择。实测新运行时返回 7 个模型，并通过 `gpt-6.1-sol` 的真实回复、重连与重试验证。

## 已实现：群聊连续发送与停止

- 首条不带 `@` 的消息交给首个启用成员；后续默认交给最近完成回复的成员。界面显示默认接收者，提交时固定目标；指定不可用成员会明确报错。
- 在 CLI 输出前绑定群聊消息与实际回复 ID；同一 Codex 成员按顺序执行，其他成员独立运行。停止会取消尚未执行的任务，并处理准备中、启动确认尚未返回的情况。
- 每次提交固定已完成的公开群聊上下文，限制旧上下文大小；不会把工具过程或半截回复当成共享结论，也不会漏掉稍后才完成的早期回复。
- 群聊运行状态包含尚未结束的提交数，某个成员先结束不会清掉其他任务的运行提示；重连快照也包含排队状态。

## 已实现：交互状态同步

- 提问、权限、后台任务及运行状态使用同一服务实例标识和递增版本；刷新与 SSE 重连返回完整快照。
- 快照晚到时重放更新的事件，拒绝旧服务实例的响应。客户端只保留有限事件；不足以补齐时自动重取快照并退避重试。
- 版本化客户端不再从历史工具文本推测当前待审批请求；原生待处理状态由设备服务提供。摘要会话也不再被误标为已加载历史。
- 10 项竞态回归、真实设备进程/HTTP SSE、Claude 断线提问与旧快照重放通过。完整权限/计划审批流程仍待后续验收。
