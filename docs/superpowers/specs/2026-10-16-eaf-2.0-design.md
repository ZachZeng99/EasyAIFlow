# EAF 2.0 设计与分阶段开发计划

状态：已确认，P0 开发中 · 日期：2026-10-16 · [实现进度](../../v2/p0-progress.md)

## 目标

将 EAF 做成统一管理多台电脑、Claude/Codex 会话和多 agent 任务的工作台，支持手机查看和操作。优先解决消息重复、乱序、遗漏，再完善群聊与协作。

## 核心设计

整体链路：桌面 / 浏览器 / 手机 → 控制入口 → 各设备常驻服务 → 本机原生 CLI 与工作区。

1. **执行与状态归设备端。** 每个会话固定归属一台设备，其常驻服务是 EAF 会话状态的唯一写入者。CLI 负责执行与原生上下文，EAF 负责可靠记录、传输和展示。Electron IPC 与 Web 桥接共同访问常驻服务，避免分别维护执行状态。关闭客户端不结束任务；设备失联显示“连接中断”，不能直接判定任务失败。

2. **统一消息记录与恢复。** 保留原生 thread / turn / item 身份，设备端分配事件序号，先持久化再广播。快照声明已包含的序号 S，客户端随后只应用 S 之后的事件；发现缺口先补齐，重复事件忽略。原生历史恢复经过同一入口，不再与实时流分别改写界面。时间戳只用于展示，不用于判断状态新旧。现有 V2 store 可复用或升级；原始协议日志用于诊断，不成为另一套状态写入源。

3. **任务提交与消息去重分别处理。** 提交、取消和审批均携带稳定请求 ID，设备端持久化受理与结果记录。重复请求返回同一操作状态。若交给 CLI 后确认丢失，标记为“执行状态待确认”，先核对原生状态；无法确认时交由用户决定，不自动重新执行。多个客户端的操作由会话所属设备串行裁决。

4. **群聊有自己的上下文规则。** 参与者具有独立 ID，可包含多个同类 provider。房间记录有序消息及其原始输出引用，并记录每次派发的确切上下文和版本。一次 `@all` 使用同一份已完成上下文；本轮回复在下一次派发时纳入，流式中间内容只展示。内部提示词、工具过程和公开回复分别处理；重试复用派发身份，避免重复注入。第一版采用明确点名与轮次。

5. **两类多 agent 共用视图，分别管理执行。** 原生子 agent 由 CLI 调度；EAF 编排的任务由 EAF 管理依赖、并行、取消和结果汇总。agent 表达执行者，任务和后台作业关联执行者，不一律建成子 agent。记录控制方、父子关系与原生身份。各 provider 结合版本与已验证的运行时发现维护能力表，覆盖模型、命令、权限、子 agent、停止和恢复；未知事件保留用于诊断。provider 适配同时负责事件转换、生命周期与控制请求。

6. **跨设备先控制，再考虑迁移。** 代码、CLI 凭据和进程留在执行设备。设备通过配对、鉴权与加密连接接入可自托管的控制入口；设备离线时继续记录，重连后按游标补齐。跨设备不依赖时钟排序：各会话由所属设备排序，房间由固定协调方排序。任务换机器执行涉及工作区和未提交改动，暂不包含在首版。

7. **模型自动更新。** Claude 与 Codex 的模型列表由已验证的运行时/SDK 接口获取，支持未知的新模型 ID，无需修改 EAF 代码或重新发版。启动、定期以及账号或运行时版本变化后自动刷新，同时提供手动刷新；缓存按设备、provider 和账号隔离，刷新失败保留缓存并显示更新时间。同步来源提供的模型名称、effort、上下文窗口和推荐默认值，缺失能力不猜测。新会话默认可跟随 provider 推荐，也可固定模型；已有会话保持选择，模型失效时提示重新选择。若发现新模型需要升级 CLI/SDK，明确提示所需更新。

8. **agent 之间可实际通信。** 原生运行时内的通信使用其已验证能力；EAF 为自己管理的 agent 提供授权团队内的定向发送、等待回复和结果回传接口，支持跨 provider、跨设备协作，无需用户手工转述。消息关联发送者、接收者、任务和回复关系，按接收者有序持久化、去重与恢复；明确区分“已入队、已交给运行时、已回复”。目标忙碌时按其能力插入或排队，离线时保留待投递状态，不假装已送达。群聊展示与任务通信共用身份和记录规则，但展示成功不能代替实际投递确认。

## Claude 集成输入

专项需求见 [Claude Code 集成需求与情报来源](../../v2/claude-code-integration-requirements.md)。本机 CLI 已核实为 `2.1.284`；专项材料引用的恢复源码为旧版，需结合当前公开接口与真实协议录制验证。

- **P0 先验证接入方式。** 比较官方 Agent SDK 与直接管理 CLI，验证认证方式、常驻运行、resume/fork、旁聊、流式输出、审批和子 agent，再决定选型。SDK 同样运行 Claude Code 二进制；认证与第三方产品适用条件需按[官方说明](https://code.claude.com/docs/en/agent-sdk/overview)核验，不能假定直接沿用现有登录方式。
- **能力按证据接入。** 公开文档、SDK 公开接口和真实录制共同验证；仅有二进制字符串的 `[BIN]` 能力作为候选，不成为核心路径依赖。发现能力失败时明确降级；已知消息缺失关键字段时报告兼容问题。
- **优先级映射。** 专项清单的 P0/P1/P2 是需求优先级，不直接对应下表阶段。权限、提问、任务完成判定、停止和恢复兼容性进入本计划 P0；子 agent 与已验证的动态能力展示进入 P1；费用、MCP 管理、Rewind、Hooks 等单独排期。

## 分阶段计划

各阶段完成验收后再进入下一阶段，不按固定日期承诺。

| 阶段 | 开发范围 | 验收标准 |
| --- | --- | --- |
| P0：可靠运行与消息 | 验证 Claude 接入选型与兼容性；拆出设备常驻服务；统一写入、快照与补发；持久化操作请求；接通两类 provider 的基础交互；提供基本手机布局 | 一台电脑运行 CLI，电脑与手机同时操作同一任务；刷新、断线、重复提交、审批、提问、排队取消后，两端消息和状态一致，任务不重复启动；关闭客户端任务继续；任务完成判定不依赖可选的 Todo 工具 |
| P1：原生子 agent、群聊与模型更新 | 模型列表自动刷新及默认模型策略；provider 动态能力展示、agent 与任务视图；支持任意参与者 ID；按固定上下文派发群聊消息 | 运行时返回此前未知的新模型后自动出现在选择器，无需改代码；断网时缓存可用，已有会话选择稳定；能查看真实子 agent 的输出与结束状态；`@all` 输入上下文一致；参与者失败、重试、停止不会串消息或让房间永久处于运行中 |
| P2：多设备管理 | 自托管控制入口、设备配对与授权、设备列表、远程命令路由、离线补发；完善手机操作 | 两台执行电脑与手机联合验证；任务、工作区和审批路由到正确设备；单台设备或控制入口断线后，其他本地任务继续，恢复后状态收敛 |
| P3：EAF 协作编排与通信 | agent 定向发送、等待回复与结果回传；任务依赖、并发限制、失败与取消传播；独立 worktree 及结果合并 | 无需人工转述，完成跨 provider、跨设备的 A→B→A 往返，以及“Codex 实现 → Claude 审查 → 修订”和一次并行任务；忙碌、离线重连与重复投递可恢复且不重复触发任务；产物、回复关联与结束状态可追踪 |

## 验证与迁移

- **P0 就建立真实协议录制与重放测试。** 按验证过的 CLI/SDK 版本与能力组合维护夹具；注入重复、延迟、断线、快照与增量交错，验证重放结果一致。保存版本、帮助与公开协议类型快照，升级时对比差异并回归，覆盖未知消息与控制请求超时。
- **区分客户端、设备服务和 CLI 的故障。** 关闭界面应继续运行；服务或 CLI 异常退出后应恢复到可解释状态，不能把未确认任务自动重跑或标成成功。
- **旧会话纳入 P0。** 先备份，以副本验证读取和迁移；新旧会话分别使用明确的写入路径，同一会话禁止双写，切换前验证原生身份映射与历史完整性。
- **阶段验收必须覆盖真实 CLI。** 现有群聊 13 项测试已通过，但未验证真实完整生命周期；当前群聊故障根因仍需复现。Claude 适配实现前对照本机 `D:\AIAgent\claude-code-sourcemap`。
- **实现检查。** 运行对应回归测试及 `npm run check`；真实运行日志、故障重放结果和迁移结果作为阶段验收依据。

## 首版边界与待定项

- 首版支持跨设备控制原机器上的任务；自动任务迁移、跨机工作区同步和无人值守多轮讨论留待后续。
- P0 确定最小支持的 CLI 版本、持久化实现及日志保留策略；P2 确定远程连接方式。先验证上述行为约束，再固定具体技术选型。
