# GPT-5.6 Sol 默认模型兼容设计

## 目标

让新建 Codex 会话默认使用 `gpt-5.6-sol`，并允许用户在聊天输入区直接选择该模型。

已有会话继续使用其持久化的模型值。现有 `gpt-5.5` 与 `gpt-5.5-mini` 选项继续保留，不迁移历史数据，也不改写恢复中的旧线程。

## 变更范围

- 将 Codex provider 的新会话默认模型从 `gpt-5.5` 改为 `gpt-5.6-sol`。
- 将 `gpt-5.6-sol` 加入 Codex 模型选择器，并作为首项显示。
- 将 `gpt-5.6-sol` 加入显式模型选择的已知值集合，避免切换会话时被错误重置。
- 原生 Codex 历史缺少模型字段时，使用新的 Codex 默认模型兜底。
- 更新直接验证上述行为的测试。

## 保持不变

- 已持久化会话的模型值不变，包括 `gpt-5.5` 和 `gpt-5.5-mini`。
- Codex app-server 的 `thread/start`、`thread/resume` 和 `turn/start` 请求结构不变；模型名继续原样透传。
- reasoning effort、提示词、工具调用、缓存、线程恢复和 token usage 解析不变。
- 不新增 Terra、Luna、Pro、显式缓存或其他 GPT-5.6 可选能力。

## 数据流

新建 Codex 会话时，session provider 提供 `gpt-5.6-sol` 作为默认值并写入会话。聊天输入区从静态 Codex 模型列表展示该值。发送消息时，现有桥接和 provider runtime 将选定模型原样传给 Codex app-server。

打开已有会话时，模型同步逻辑优先使用会话中持久化的模型，因此不会被新的全局默认值覆盖。

## 错误与兼容处理

应用不自行判断账户是否有 GPT-5.6 Sol 权限。若本机 Codex CLI 或账户不支持该模型，沿用现有 app-server 错误展示路径，把运行时错误返回给用户。

旧模型仍在选择器中，可作为用户主动选择的回退项。此次变更不做静默自动回退，避免请求模型与实际模型不一致。

## 测试

- provider 默认模型测试：Codex 默认值为 `gpt-5.6-sol`。
- 模型同步测试：显式选择 `gpt-5.6-sol` 时保持选择；已有 `gpt-5.5` 会话仍保持旧值。
- 聊天输入区测试：Codex 模型选项包含 `gpt-5.6-sol`，并保留旧模型。
- 原生 Codex 导入测试：缺少模型字段时使用新默认值；带旧模型字段时保持原值。
- 运行相关单元测试与 `npm run check`。

## 完成标准

新建 Codex 会话默认显示并请求 `gpt-5.6-sol`；用户可以选择保留的旧模型；已有会话不会被迁移；相关测试和 TypeScript 类型检查通过。
